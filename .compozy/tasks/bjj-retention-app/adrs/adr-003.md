# ADR-003: Cliente mobile — React Native + Expo

## Status

Accepted

## Date

2026-06-30

## Context

O produto é greenfield, mobile-first e centrado em vídeo vertical 9:16 com experiência imersiva. A distribuição no piloto se dá por link enviado via WhatsApp pelo professor, e o MVP precisa ser construído rapidamente, de preferência com base de código única para iOS e Android.

## Decision

Construir o cliente em **React Native com Expo** (TypeScript). O piloto será distribuído por canais de teste (TestFlight no iOS e build interno/APK no Android, ou Expo internal distribution), e o link de WhatsApp aponta para a instalação ou, quando o app já estiver instalado, abre via deep link na "Semana Atual".

## Alternatives Considered

### Alternative 1: PWA (web app instalável)

- **Description**: Aplicativo web instalável aberto diretamente pelo link do WhatsApp, sem app store.
- **Pros**: Menor atrito de distribuição; abre direto pelo link; sem submissão a lojas.
- **Cons**: Reprodução de vídeo fullscreen vertical e gestos imersivos menos consistentes em PWA; integração nativa mais limitada.
- **Why rejected**: Optou-se por experiência nativa de player e melhor desempenho de consumo de vídeo.

### Alternative 2: Flutter

- **Description**: App nativo iOS/Android com base única em Dart.
- **Pros**: Desempenho nativo; base única.
- **Cons**: Ecossistema de integração com Supabase menos maduro que o de React Native; nova linguagem/toolchain para o projeto.
- **Why rejected**: React Native + Expo oferece caminho mais rápido com integração madura a Supabase e TypeScript.

### Alternative 3: Nativo separado (Swift + Kotlin)

- **Description**: Dois apps nativos independentes.
- **Pros**: Máximo controle por plataforma.
- **Cons**: Dobra o esforço; sem base única; incompatível com prazo de MVP.
- **Why rejected**: Custo incompatível com um teste de validação.

## Consequences

### Positive

- Base de código única em TypeScript para iOS e Android.
- Player nativo de vídeo para experiência vertical imersiva.
- Iteração rápida com o ecossistema Expo.

### Negative

- Distribuição no piloto exige builds de teste (TestFlight/APK), com mais atrito que um link web puro.

### Risks

- Atrito de instalação pode reduzir adesão inicial — mitigado por instruções claras no aviso de WhatsApp e contas já criadas.

## Implementation Notes

Usar Expo Router para navegação. O deep link do WhatsApp deve resolver para a tela de "Semana Atual" quando autenticado, ou para login caso contrário.
